# Trippin' AI

A group trip planner for Android that helps friends align on travel plans through interactive voting. Travel companions create a trip, suggest places to visit, and swipe on destination cards to build consensus. The highest-voted stops are turned into a day-by-day itinerary with shared expense tracking and live updates.

## What you can do

- **Swipe to vote.** Swipe right to like a place, left to pass, up for a must. The app shows where the group agrees.
- **Ideas and votes.** Anyone can suggest a destination or a place. Votes are counted per person.
- **Plan.** Turn the favourite places into a route for each day.
- **Budget.** Record expenses and split them between the people on the trip.
- **People.** Invite friends with a code or a link.
- **Today.** See what is happening now while you travel.

## How it is built

- Kotlin and Jetpack Compose (Material 3), minimum Android 8.0 (API 26).
- Room for data stored on the phone.
- Firebase sign-in and Firestore for sharing a trip with friends. Without a Firebase file the app still runs in an on-device mode.
- Foursquare Places for place search and photos. Without a key the app falls back to free OpenStreetMap search.
- A separate pure-Kotlin module, `intelligence/`, holds the planning logic: group voting and consensus, expense splitting, route ordering with a genetic algorithm, a fuzzy fatigue model, a Bayesian risk model and a Q-learning recommender.

## Run it

1. Install Android Studio and open this folder. Use JDK 17.
2. Optional: put your `google-services.json` in `app/` to turn on Firebase.
3. Optional: add `FOURSQUARE_API_KEY=your_key` to `local.properties` to turn on Foursquare.
4. Press Run.

Neither optional file is ever committed.

## Architectural Principle
Trippin' AI rejects hallucinated or physically unfeasible schedules. Every candidate schedule generated by AI must pass a **Deterministic Itinerary Engine** before being saved or shown to the traveler:
-  **No Temporal Overlaps**
- **Respects Venue Operating Hours**
- **Guarantees Realistic Route Travel Times Between Venues**
- **Respects Traveler Pace & Fatigue Constraints**
- **Adheres to Total Budget Limits**

## 🚀 Getting Started

### Prerequisites
- **Node.js**: >= 20.x (tested on v25.x)
- **pnpm**: >= 10.x
- **Docker**: For PostgreSQL + PostGIS and Redis
- **Android Studio / SDK**: Android 15 (API 35) with Java 21+

### 1. Install Dependencies
```bash
pnpm install
```

### 2. Start Local Database & Cache
```bash
pnpm db:up
# Or: docker compose -f infrastructure/docker/docker-compose.yml up -d
```

### 3. Setup Database Schema & Seed Data
```bash
pnpm db:generate
pnpm db:migrate
pnpm db:seed
```

### 4. Run the Backend in Development
```bash
pnpm backend:dev
```
- API Endpoint: `http://localhost:4000/api/v1`
- Swagger OpenAPI Docs: `http://localhost:4000/api/docs`

### 5. Run the Automated AI Evaluation Suite
```bash
npx ts-node test-cases/run-eval.ts
```

### 6. Open Android Project
Open `apps/android` in Android Studio or build via Gradle:
```bash
cd apps/android
./gradlew assembleDebug
```

##  API behaviour clients must know

**Writes need an identity, reads do not.** `GET` routes are open so a shared trip link works for anyone.
`POST` routes (create trip, generate, modify, vote) require either an `Authorization: Bearer <token>` or an
`X-Guest-Session: <any stable id>` header. The web app and the Android app both generate a random id on
first run and send it on every request, which gives each browser and each install its own account instead of
a shared demo user. Without a header a write returns `401`.

**Opening hours are labelled.** `place.openingHoursEstimated` is `true` when the hours came from the venue
category rather than a published source. The engine never rejects a schedule for a venue with estimated
hours, and any UI should show them as an estimate rather than as fact.

**Schedules are only `VERIFIED` when the engine passed them.** `itinerary.status` is `DRAFT` when validation
found unresolved violations after the repair budget was spent. The deterministic generator runs as a
fallback before that happens. Clients should render drafts with a visible warning instead of hiding them.

**Rate limits.** 60 requests per minute per IP by default, 10 on trip creation, 5 on generation, 6 on
modification, 30 on voting. Tunable with `RATE_LIMIT_PER_MINUTE`. Over the limit returns `429`.

**Switches.** `CORS_ORIGINS` (comma separated, otherwise `*` without credentials), `SWAGGER_ENABLED=false`
to turn `/api/docs` off in production, `AUTH_BYPASS_DEV=true` for local work without a session header.

##  Two traps in this folder name

The project directory is `Tripp'in`, and the apostrophe breaks two toolchains:

1. `pnpm backend:dev` (`nest start --watch`) dies with `Syntax error: Unterminated quoted string` because
   Nest interpolates the path into a shell command. Run the compiled server instead:
   `node apps/backend/dist/src/main.js`.
2. Next.js metadata routes (`src/app/robots.ts`, `sitemap.ts`, `icon.svg`) fail the webpack build with
   "Default export is missing". This repo keeps `robots.txt`, `sitemap.xml` and `favicon.svg` in
   `apps/web/public/` instead, which also serves them faster from the CDN.

Both disappear if the folder is renamed without the apostrophe, but nothing here depends on that...
